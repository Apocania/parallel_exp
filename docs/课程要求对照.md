# 课程要求与实现对照

依据工作目录中五张课程照片整理。照片明确要求与本项目的实现取舍分开列出。

| 课件要求 | 本项目对应内容 | 验证位置 |
|---|---|---|
| 分区时仍能修改购物车 | 每个可达节点本地提交后确认 | `test_10` |
| 同一用户手机/电脑并发修改，不覆盖新增 | 两个客户端连接 A/B；添加事实合并 | 面板分步引导、`test_10` |
| CRDT | 基于状态的 OR-Set 商品实例；添加/删除并集合并 | `crdt.py`、随机合并性质测试 |
| 版本向量 | 持久化身份与逻辑计数，比较因果/并发 | 节点向量、`test_vector_partial_order` |
| 冲突合并 | 并发新增保留、观察删除、并发添加优先 | `test_20` |
| 一个副本突然宕机 | 停止节点进程，其他节点继续服务 | `test_50` |
| 双向分区、重复三次 | 双向门控、同一状态排队三份 | `test_10`、`test_40` |
| 消息延迟 10 秒、乱序 | 单调时钟排队、额外延迟产生越序 | `test_40` |
| 重启后内存丢失 | SQLite 恢复状态、版本、去重；补同步 | 持久化单元测试、`test_30/50` |
| 新节点迁移一半宕机 | 暂存、校验、原子提交、失败重新导入 | `test_90` |
| 某 key 占 50% 请求 | 固定热点占比的并发压力脚本 | `test_80`、`benchmark.py` |
| 两客户端同时 CAS | 单节点 CAS 竞争；跨节点边界对照 | `test_70` |
| 时间倒退一分钟 | 可注入时钟偏移，逻辑计数不回拨 | `test_60` |
| 写成功、响应丢失 | 代理丢成功响应，沿用请求 ID 重试 | `test_30` |
| 预测→注入→对照→解释 | 分步引导、实验清单、演示讲稿 | `演示流程.md` |
| Docker/虚拟机/其他模拟方式 | 本机独立进程；另附单容器多进程配置 | README；Docker 配置未本机实测 |
| GitHub 代码及完整 README | 源码、测试、README 已准备 | 尚待选择仓库并上传 |
| 一份报告、现场 PPT | 提供技术说明、实验数据、汇报提纲 | 尚需由小组结合实测理解完成正式报告/PPT |
| 报告和 PPT 首页写仓库链接 | 汇报提纲含待填写位置 | 获取实际 GitHub 地址后填写 |

实现额外包含跨节点同 ID 添加去重、并发数量语义说明、节点原始元数据与事件导出，方便追问时给出证据。

课件写的是“至少考虑”上述故障。本项目通过代码与实验覆盖，但没有引入分片、共识、全局事务或生产级容错框架。不要把局部演示的保证扩大到未实现的系统范围。
