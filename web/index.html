      LEARN THE EXPERIMENT
      每一步，为什么这样做？
      先理解问题，再操作；最后用观察到的结果解释原理。
      完整讲解 / 打印 ↗
      
      
      先分清这三层
      手机、电脑是两个操作入口，属于同一用户；A、B、C是独立运行、独立存储的服务器副本；节点之间的同步消息把购物车修改传播给其他副本。分区切断的是节点之间的通信，宕机停止的是节点进程。
      每次独立添加都会产生一个商品标记。界面数量是仍然有效的标记数；同步时合并标记与删除记录。牛奶是每次实验的初始参照商品。
      
      
      
      
      
    
      
    
      
      
      UNDER THE HOOD
      每一份数据，都有来处。
      把业务语义、因果关系和系统保证放在一起理解。
      
      
      
        
      01
      每次添加是一件商品
      每件商品有独立的添加标记。同一请求在另一个节点重试，会产生相同标记；两次独立添加则产生两个标记，数量为 2。
      数量 = 未被删除的添加标记数
      减一移除客户端看到的一个标记；移除商品删除客户端看到的所有该商品标记。两个客户端并发删除同一件商品，合并后只删除一件。
      
        
      02
      删除已经观察到的添加
      A 删除旧苹果，B 并发添加新苹果。同步后，旧标记被删除，新标记仍在。这就是并发添加优先。
      添加集合取并集 · 删除记录取并集
      再次读取并删除后，新苹果也能被移除。删除记录不会在这个实验中清理，避免旧副本带回已经删除的商品。
      
        
      03
      版本向量记录因果关系
      每个节点拥有独立身份和持久化的逻辑计数。{A:2, B:1} 与 {A:1, B:2} 彼此并发，不能互相覆盖。
      版本分量取最大值 · 商品按 CRDT 合并
      本系统完整状态交换保留所有元数据；版本向量用于展示因果与识别并发，不单独用来丢弃购物车内容。
      
        
      04
      写成功，意味着什么？
      本节点的商品、版本计数和请求记录在一个 SQLite 事务中提交后返回成功。此时确认的是 1 个本地副本。
      本地持久化 → 返回成功 → 异步传播
      其他副本可能读到旧值。进程重启可从磁盘恢复；尚未复制的唯一磁盘副本永久损坏，仍可能丢数据。
      
        
      05
      重复投递与请求重试
      状态合并满足交换律、结合律和幂等律。消息乱序、重复，仍能得到相同结果。
      请求去重则使用请求 ID 与操作指纹。客户端必须沿用原请求内容和 ID。分区中将同一 ID 用于不同操作无法被全局即时拒绝；合并后会显示 ID 冲突。
      
        
      06
      实验的边界
      三个副本是独立进程、独立数据库。消息经实验控制器转发，便于注入故障；控制器故障会影响同步和面板。
      CAS 演示仅保证单节点原子性。节点加入使用完整快照、暂存、校验和原子提交。本项目没有全局事务、库存扣减或支付逻辑。
