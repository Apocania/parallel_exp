# CartLab：分布式购物车实验室

面向“并行与分布式计算”课程的可运行实验系统。支持网络分区期间的本地写入、购物车并发合并、故障注入和可观察的恢复过程。

核心技术：**基于状态的 OR-Set 商品实例模型、版本向量、请求去重、SQLite 持久化、HTTP 异步复制**。

## 快速启动

需要 Python 3.10 或更新版本。应用和测试只使用 Python 标准库，没有 pip 或 npm 安装步骤。

```powershell
cd E:\parallel
python -X utf8 run.py
```

打开 <http://127.0.0.1:8760>。从顶部选择场景，点击“准备本次实验”，再按步骤完成操作。每一步都有预期和实际验证结果。简洁讲解见 [演示流程](docs/演示流程.md)。

终端保持运行。按 `Ctrl+C` 关闭控制器及其启动的节点；节点数据库保留。节点 A、B、C 的内部端口分别是 8761、8762、8763；加入实验的节点 D 使用 8764。

换端口或使用全新的实验数据库：

```powershell
python -X utf8 run.py --port 8860 --node-base-port 8861 --data-dir .lab-data-session2
```

切换场景或“重新做本实验”会创建新的购物车 ID，解除故障、启动 A/B/C，并停止 D 的上一轮导入，不删除此前实验数据。旧购物车仍保存在节点数据库中，可用 API 的 `cart_id` 查询。导出的 JSON 包含购物车 ID 和各步骤的实际验证结果。

正常写入后立即触发复制，页面通过 SSE 接收变化通知后重新读取实际节点状态；不再等待“节点每秒同步＋页面每秒轮询”。本地返回先更新操作端，另一端只有读到真实更新才改变。周期完整同步保留作为消息丢失后的修复机制。

“消息怎么走”按用户操作固定保留记录；可以选择旧操作查看，后台无变化的消息不刷屏。后台默认约 10 秒补同步一次，可用 `--sync-interval` 配置；写入、恢复和重启仍立即同步。商品状态与消息进度使用不同通知，消息进度查询不再读取所有节点。原始日志按需展开、手动读取，不自动滚动。

不清楚每个实验的意义时，点击步骤卡下方“看懂这个实验”或左侧“实验讲解”。完整说明包含系统结构、11 个实验的逐步操作与原理、通过判据、边界、常见问题、展示讲稿和 18 项术语：[详细讲解](docs/实验讲解详解.md) · [可离线打开及打印的 HTML](docs/实验讲解详解.html)。内容源为 `web/lessons.js`，修改后运行 `python -X utf8 tools/build_guide.py` 同步生成文档。

## 可以演示什么

从首页进入[自由实验台](http://127.0.0.1:8760/free)，可以在手机和桌面两个购物窗口中点选商品、加减数量或整行移除。手机默认读节点 A，桌面默认读 B。每个窗口显示所选节点的商品、合计金额、最近一次数量变化和本端请求回执。上方逐种比较商品，件数相同但品种不同也能看出差异。窄屏顶部可定位到手机、桌面或实验工具。

顶部可以暂停自动投递或一键复位。在实验工具中，节点矩阵的行是来源，列是目标。每个方向都可以单独断链、复制、延迟或丢包。暂停投递后，在队列选一份快照立即投递，就能看到目标窗口何时收到商品。勾选“显示后台包”可查看待投递的周期修复消息。

CAS 面板允许指定键、节点、期望版本与值，两个请求可以同时发送。分步迁移允许任选不同的来源和目标、逐片发送、单独提交、中断后重取快照。初次准备会为目标创建新数据库，保留原库。热点压测支持在页面选节点、并发数和热点比例。展开“如何自行验证各项实验”可查阅 11 个操作示例；在“观测记录”保存前后对照或导出。

自由实验与引导页共享节点和故障设置。自由复位会新建空购物车、恢复 A/B/C、停止 D、清除排队消息、迁移、时钟与故障并恢复自动投递。本页对照和操作回执可在复位前导出。旧购物车保存在节点数据库中。CAS 键按本轮购物车 ID 区分。

| 场景 | 操作与预期 |
|---|---|
| 正常双向同步 | 手机添加苹果，电脑自动更新；电脑移除后，手机也自动更新 |
| 分区期间修改 | 隔离 A，手机经 A 添加苹果、电脑经 B 添加饼干；两边成功，恢复后都保留 |
| 并发添加/删除 | 两端都看到旧苹果，分区后一端删除、一端再次添加；新的添加存活 |
| 商品数量 | 每次独立添加是一件；重复请求是同一件；减一删除一个已观察标记 |
| 重复投递 | 每条同步消息发三次，数量不重复增加 |
| 延迟与乱序 | A 先添加再删除，旧快照约 12 秒、新快照约 10 秒；核对后发先到和苹果不复活 |
| 写后响应丢失 | 丢弃 A 的下次成功响应；客户端同 ID 重试，服务器识别重复 |
| 副本宕机 | 停止真实节点进程，其余节点仍可写；启动后从磁盘恢复并补同步 |
| 时钟回拨 | A 的实验时钟减 60 秒，逻辑版本仍递增 |
| 加入时失败 | D 的初始快照写入暂存区；中途停止 D，未完成副本不服务；重试后校验并提交 |
| 热点请求 | 压测脚本将 50% 请求发给同一 key，测量延迟、吞吐和最终数量 |
| CAS 对照 | A 上两个请求竞争同一版本，只允许一个成功；跨副本不提供全局 CAS |

## 运行测试与压测

```powershell
python -X utf8 -m unittest discover -s tests -v
```

共 33 项测试，使用临时端口、独立进程和隔离的数据目录。其中 11 项覆盖数据结构与持久化，11 项覆盖故障集成，5 项覆盖即时同步与指定乱序，3 项覆盖消息观测，另有 3 项覆盖自由实验的单向链路、逐条投递、复位和分步迁移。即时同步专项将周期同步设为 60 秒。消息观测专项验证后台修复运行时，关键记录和界面通知版本保持稳定。真实延迟与进程恢复会使测试花费一分钟以上。

集成测试观测结果写入 `artifacts/` 下的 `integration-results.json`、`realtime-results.json`、`message-results.json` 和 `free-control-results.json`。每次运行请结合测试退出码和终端输出判断结果。可读记录见 [实验记录](docs/实验记录.md)。

启动面板后，运行热点压测：

```powershell
python -X utf8 tools/benchmark.py --requests 120 --workers 8
```

结果写入 `artifacts/benchmark.json`。全部请求经控制器访问节点 A，其中 50% 访问同一个购物车，其余访问不同购物车；后台复制保持运行。该实验测量本机这个原型的表现，不代表生产系统容量，也不是分片方案对比。

可将 `--url` 改为自己的控制台地址。压测使用独立购物车 ID，不改变当前演示购物车的内容。

## Docker

```sh
docker compose up --build
```

打开 <http://127.0.0.1:8760>。使用 `docker compose down` 停止，命名卷保留数据库。

此配置在一个容器内运行控制器和三个独立节点进程，每个节点有独立数据库；节点隔离由消息层模拟。它不是三个容器之间的真实网络隔离。当前开发机器未检测到 Docker，容器配置未在本机运行验证；已验证的是本机 Python 运行方式。

## 关键保证与边界

- **写成功 = 当前节点的一个 SQLite 事务已提交**。事务包含购物车状态、逻辑计数和请求记录，不表示所有副本已保存。
- **分区可写**的前提是客户端可达的节点和它的本地存储可用。本项目没有实现完全离线浏览器的本地编辑缓存。
- **收敛依赖更新最终充分传播**。周期完整状态交换修复丢失消息；断网时不承诺读到其他分区的新值。
- **并发删除同一件只删除一件**。这采用“删除已观察商品实例”的语义；不是两个并发 `−1` 必须总计减二的计数器语义。
- **每个用户意图必须有新的请求 ID，重试沿用 ID 和完整操作内容**。同节点发现 ID 被用于不同内容会拒绝；分区间的 ID 误用合并后记录冲突，不能全局即时拒绝。
- **进程重启不等于磁盘永久损坏**。未复制的唯一持久化副本永久丢失，CRDT 无法恢复它。
- 不清理删除记录或去重元数据；全状态同步与全副本存储只适合小规模教学。运行很多次压测后可改用新的数据目录。
- 控制器是实验控制面和消息转发单点，关闭它会影响面板与同步。节点本身有独立存储与服务端口。
- 页面“状态一致”只比较当次可读取且可服务的节点；显示比较范围。事件通知后的读取也不是分布式原子快照或形式化证明。分步验证还会核对指定节点均可服务、具体商品数量与完整状态哈希。
- 迁移实验可重复执行；每轮使用新的 D 数据库并保留旧数据。导入在一半处暂停，便于观察中断；失败后可在本轮数据库上重试。
- CAS 为单节点对照实验，不参与购物车合并，不提供全局强一致性。
